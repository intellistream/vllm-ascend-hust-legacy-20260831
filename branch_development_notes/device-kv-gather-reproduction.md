# Device KV Gather Prototype Reproduction

Generated on 2026-06-18.

## Purpose

This note records how to reproduce the experimental
`kv_cache_block_gather` prototype from this `vllm-ascend-hust` branch alone.

The reproduction path should not depend on `tmp/cann-stack` or any separate
custom-op source repository. That directory was only source material used during
the extraction. After integration, the branch itself contains the custom
operator implementation, the build-chain hook, the Python torch binding, and the
direct smoke test.

This is a prototype smoke. It proves that the custom ACLNN op can be built,
registered, loaded, and executed in Docker on one NPU. It does not attempt to
prove production readiness for long-running CPU offload, scheduler interaction,
request cancellation, or resource-leak safety.

The reproduction depends on these in-branch files:

- `csrc/kv_cache_block_gather/op_kernel/*`

## One-Shot Docker Reproduction

From the host:

```bash
REPO=/home/jingyuan/workspace/vllm-ascend-hust
IMAGE=quay.io/ascend/vllm-ascend:v0.16.0rc1-openeuler

docker run --rm --privileged --network=host --ipc=host \
  --device /dev/davinci0 \
  --device /dev/davinci_manager \
  --device /dev/devmm_svm \
  --device /dev/hisi_hdc \

  -v /usr/local/sbin/npu-smi:/usr/local/sbin/npu-smi:ro \
  -v "$REPO":/workspace/vllm-ascend-hust-src:ro \

  /bin/bash -lc '

if [ -f /usr/local/Ascend/ascend-toolkit/set_env.sh ]; then
  source /usr/local/Ascend/ascend-toolkit/set_env.sh

  source /usr/local/Ascend/cann-8.5.1/set_env.sh

export ASCEND_RT_VISIBLE_DEVICES=0
export ASCEND_VISIBLE_DEVICES=0

rm -rf /tmp/vllm-ascend-hust

test -f csrc/kv_cache_block_gather/op_kernel/kv_cache_block_gather.cpp
```

## Why The Opapi Env Var Is Set

`torch.ops._C_ascend.kv_cache_block_gather` is registered by
`vllm_ascend_C`, but the wrapper resolves the actual ACLNN symbols at runtime.
The CANN image's built-in `libopapi.so` does not provide this experimental
symbol. The branch build generates a custom opapi library instead:

```text
vllm_ascend/_cann_ops_custom/vendors/vllm-ascend/op_api/lib/libcust_opapi.so
```

The smoke therefore sets:

```bash
export VLLM_ASCEND_CPU_OFFLOAD_HOST_GATHER_OPAPI_LIB=$CUSTOM_OPP/op_api/lib/libcust_opapi.so
```

Without that override, the op registration may still succeed, but execution can
fail with:

```text
RuntimeError: aclnnKvCacheBlockGather or
aclnnKvCacheBlockGatherGetWorkspaceSize not found in op_api libraries
```

## Troubleshooting

If `has gather False`:

```text
vllm_ascend.vllm_ascend_C was not imported or did not build correctly.
Check the editable build logs and confirm vllm_ascend_C*.so exists.
```

If ACLNN symbols are missing:

```text
Check that csrc/build_aclnn.sh includes kv_cache_block_gather.
Check that csrc/kv_cache_block_gather/op_host/CMakeLists.txt is included by
the custom-op build.
Check nm -D on the generated libcust_opapi.so.
```

If the runtime cannot find the custom kernel implementation:

```text
Check ASCEND_CUSTOM_OPP_PATH points to
vllm_ascend/_cann_ops_custom/vendors/vllm-ascend.
If needed, source $CUSTOM_OPP/bin/set_env.bash before running the smoke.
```

If Docker hangs when probing an existing long-running container:

```text
Prefer /bin/sh -c for simple docker exec probes. Some images can hang in
bash -lc login-shell initialization.
```

Pip dependency warnings from the checked image were observed but did not block
the custom-op build or direct smoke.

## Validation Boundary

This reproduction validates:

```text

custom opapi library is packaged into vllm_ascend/_cann_ops_custom
```

This reproduction intentionally does not validate:
