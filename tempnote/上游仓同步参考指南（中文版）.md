# 上游仓同步参考指南

## 基本流程

1. 配置 upstream remote：`git remote add upstream https://github.com/vllm-project/vllm-ascend.git`
2. Fetch 上游最新：`git fetch upstream`
3. 创建同步分支：`git checkout -b sync-branch main`
4. 批量 cherry-pick：按 PR 列表逐个 `git cherry-pick <commit>`
5. 解决冲突：按冲突解决规则处理
6. 推送并创建 PR

## Cherry-Pick 策略

### 无冲突 PR
直接 `git cherry-pick <commit>`，自动合并。

### 有冲突 PR
1. `git cherry-pick <commit>` → 出现冲突
2. `git status` 查看冲突文件
3. 按冲突决策流程解决（见《冲突解决规则》）
4. `git cherry-pick --continue`

### 复杂度阈值
- 冲突文件 **>10 个** → `git cherry-pick --abort`，标记 🔍 待人工
- 涉及 **C++ 自定义算子、平台层核心代码** → abort，标记 🔍
- 冲突含 CUDA/ROCm 专用代码 → `--ours`（Ascend 不需要）
- **不确定** → `--ours` 保护 HEAD + 标记 🔍 待确认

### 空提交
如果冲突解决后 cherry-pick 变为空（HEAD 已含改动）：
- `git cherry-pick --skip`

## 批量脚本

```bash
#!/bin/bash
prs="8574 9303 9916 ..."
for pr in $prs; do
  c=$(git log upstream/main --oneline --grep="#$pr" --format="%H" | head -1)
  echo -n "PR #$pr: "
  if git cherry-pick "$c" 2>&1 | grep -q "CONFLICT\|error"; then
    echo "❌ CONFLICT"
    git cherry-pick --abort
  else
    echo "✅"
  fi
done
```

## 注意事项

- Cherry-pick 后的 commit hash 会变，检测合并状态需用 PR 号而非 hash
- `git clean -fd` 会删除未跟踪文件（包括 tempnote/），慎用
- 推送前检查 `git status` 确保无遗漏文件
